# Smoking Relapse Prediction: Proposal Review and Implementation Plan

## Overall assessment

The project is feasible for CSE366. The strongest initial version is an explainable model that predicts whether a former smoker will report smoking at the next PATH survey. The main work is defining the cohort correctly, matching variables across waves, and preventing data leakage.

This review covers the text of `Smoking_Relapse_Predictor_Presentation.pptx`, profiles of all eight adult TSV datasets, and relevant codebook definitions. No predictive model has been trained as part of this analysis.

### Preliminary cohort check

For each adjacent-wave pair, the preliminary cohort uses these rules:

- At the starting wave: former established smoker and no cigarette smoking in the past 30 days.
- At the following wave: a valid past-30-day smoking response.
- Positive outcome: reports smoking in the past 30 days at follow-up.

This gives **30,890 person-wave records and 3,258 positive outcomes** before feature exclusions. People can appear in multiple pairs, so these are not unique participants. These are preliminary, unweighted counts, not population relapse estimates or final cohort sizes.

Reproducible calculations are available in [.analysis/cohort_counts.json](.analysis/cohort_counts.json), generated by [.analysis/cohort.cjs](.analysis/cohort.cjs).

The dataset is large enough for a meaningful project. The observed class imbalance should drive the methodology. The proposal's 7% successful-cessation figure from another study does not establish the relapse rate in this cohort.

## 2. Recommended project definition

### Research question

> Among former established cigarette smokers who report no smoking in the past 30 days, how well can information available at the current interview predict smoking at the next interview?

### Suggested title

**Explainable Prediction of Smoking Resumption Among Former Smokers Using Longitudinal PATH Data**

Smoking resumption accurately describes the proposed endpoint. A past-30-day smoking response does not establish the exact relapse date, persistent regular smoking, or continuous abstinence between interviews.

### Stricter alternative cohort

Use three waves:

1. Smoking at wave t-1.
2. Abstinent at wave t.
3. Smoking status at wave t+1 as the outcome.

This captures an observed cessation transition, but reduces the sample. Start with the larger former-smoker cohort and evaluate recent quitters separately. Calculate the stricter cohort size before committing to it.

## 3. Implementation plan

### Step 1: Create a variable dictionary

Before modeling, map each selected variable to:

- A common feature name.
- Its wave-specific column.
- Value labels and units.
- Missing-value codes.
- Question eligibility and skip rules.
- Whether the information is available at prediction time.

Start with approximately 20 to 40 interpretable features. Candidate feature groups include:

| Feature group | Candidate information |
|---|---|
| Demographics | Age, sex, education, income |
| Smoking history | Time since quitting, previous smoking intensity, previous quit attempts |
| Other tobacco use | E-cigarettes and other tobacco products |
| Social environment | Household smoking and smoking rules |
| Health and behavior | Mental health indicators and alcohol use |

Each candidate must be checked for availability and applicability to former smokers. Historical dependence or smoking-intensity questions may require earlier-wave information rather than current-wave responses.

Confirmed cohort and outcome variables include:

| Purpose | Wave 1 example | Wave 2 example |
|---|---|---|
| Former established smoker | `R01R_A_FMR_ESTD_CIGS` | `R02R_A_FMR_ESTD_CIGS_REV` |
| Current established smoker | `R01R_A_CUR_ESTD_CIGS` | `R02R_A_CUR_ESTD_CIGS` |
| Past-30-day smoking | `R01R_A_P30D_CIGS` | `R02R_A_P30D_CIGS` |

These indicators use **1 = Yes and 2 = No**, rather than 0 and 1.

Wave 2 lacks the same derived cigarette days-since-quitting column found in several other waves. Its raw number/unit questions require separate handling and attention to skip patterns. Missing information must not be interpreted as zero days since quitting.

Relevant local references:

- [Wave 1 codebook](PATH/DS1001/36498-1001-Codebook.pdf)
- [Wave 2 codebook](PATH/DS2001/36498-2001-Codebook.pdf)
- [Wave 8 codebook](PATH/DS8001/36498-8001-Codebook.pdf)

### Step 2: Build the longitudinal analysis table

Create one row per eligible person and prediction interval. Join waves using `PERSONID`.

A conceptual row contains:

```text
PERSONID | starting_wave | baseline_features | next_wave_smoking_outcome
```

Keep identifiers for joining and splitting, but exclude them from model features. Use current and earlier-wave information as predictors. Use the next wave only to construct the outcome.

Do not treat an absent follow-up interview or missing outcome as sustained abstinence.

The existing `PATH/TSV/filter_all_waves.py` keeps only participants present in all eight waves and produces 11,457 IDs. **Do not use that intersection as the default cohort.** Adjacent-wave prediction only requires the relevant interviews. Requiring all eight excludes later entrants and selects long-term responders.

Read selected columns directly from the TSV files. Converting every full file to CSV is unnecessary for this task.

### Step 3: Handle missingness according to the questionnaire

PATH contains refusal, unknown, skipped-question, removed-response, and system-missing codes. A skipped question can mean something different from an unanswered question.

Begin with:

- Median imputation for numeric features where appropriate.
- Explicit missing or not-applicable categories for categorical features.
- Missingness indicators where useful.
- Separate handling of structural skips based on questionnaire routing.

Fit all preprocessing on training data only. MICE can be a later comparison rather than a starting requirement.

### Step 4: Establish baselines and compare models

Compare:

1. A prevalence-only baseline.
2. Logistic regression.
3. Random Forest.
4. XGBoost.

A useful experiment compares a small model using demographics and time since quitting against the fuller feature set. This tests whether additional survey questions provide meaningful predictive improvement.

Start with class weights. Test sampling only if needed. Ordinary SMOTE can produce invalid combinations of encoded survey categories. SMOTENC or random oversampling are more appropriate comparisons for mixed survey data.

Apply any sampling inside training folds only. Preserve the original outcome prevalence in validation and test sets. If weighting or resampling changes probability calibration, evaluate calibration and perform any recalibration using validation data only.

### Step 5: Prevent participant and temporal leakage

For pooled person-wave records, use participant-grouped cross-validation. The same person must not enter both training and validation sets in that evaluation.

Add a later-wave evaluation. For a strict future-participant test:

- Reserve a participant group for Wave 7 to Wave 8 evaluation.
- Exclude those people's earlier records from training.
- Train and tune using the remaining participants and earlier prediction intervals.
- Evaluate once on the reserved later-wave test data.

Document the split clearly. An ordinary time split can still contain the same participants on both sides. A test involving returning participants answers a different question from a test involving previously unseen participants.

Feature selection, imputation, encoding, resampling, hyperparameter tuning, calibration, and threshold selection must respect the split boundaries.

### Step 6: Evaluate probabilities and classifications

Report:

| Metric or output | Purpose |
|---|---|
| PR-AUC / average precision | Assess positive-case identification under imbalance; specify the exact calculation |
| ROC-AUC | Assess ranking across thresholds |
| Precision and recall | Show reliability and coverage of positive predictions |
| Specificity | Show identification of negative outcomes |
| Confusion matrix | Show errors at the selected threshold |
| Brier score | Assess probability prediction error |
| Calibration plot | Compare predicted probabilities with observed frequencies |

Select the classification threshold using validation data, not the final test set. Report the positive prevalence alongside PR-AUC or average precision.

At approximately 10% positive prevalence, predicting everyone as negative gives about 90% accuracy. Accuracy alone would therefore be misleading.

When estimating uncertainty from repeated person-wave records, bootstrap by participant rather than independently by row.

### Step 7: Explain the model and build a demonstration

Use SHAP for global feature patterns and individual prediction explanations. Describe the results as model associations rather than causes.

A small Streamlit demonstration can show:

- Input questions corresponding to the trained feature set.
- Estimated next-wave smoking probability.
- Features contributing to that prediction.
- A clear research-prototype label and a description of the prediction endpoint.

Keep the demonstration's input questions, preprocessing, and category definitions consistent with the model. Do not imply clinical validation or prescribe treatment based on the prediction.

## 4. Changes needed in the proposal

### Resolve the title and methodology mismatch

The subtitle promises time-to-relapse, while the methods describe binary classification. Keep next-wave classification as the core project.

A later extension could model time to first observed smoking resumption using interval-aware survival methods. Repeated survey observations do not automatically reveal an exact relapse date, and temporary smoking episodes between interviews may be missed.

### Update the novelty claim

A paper published online in 2025 already applies Random Forest to smoking relapse using PATH:

[Machine Learning of Smoking Relapse: the Role of Racial Differences and E-Cigarette Vaping Characteristics on Former Smokers](https://pubmed.ncbi.nlm.nih.gov/40117048/).

The proposal should discuss this paper directly. Avoid claiming that PATH-based relapse prediction is unaddressed.

Possible contributions for this course project include:

- Validation across later waves.
- Calibrated probability estimates.
- Separate evaluation of recent and long-term quitters.
- A reproducible cohort and variable-harmonization process.
- Comparison of a compact feature set against a fuller survey model.

These are candidate contributions, not claims of established novelty without further literature review.

### Correct the literature metric

The Issabakhsh paper reports **72% balanced accuracy and 0.76 ROC-AUC** for its best model. Specify the metric accurately rather than presenting the result only as generic accuracy.

Source: [Machine learning application for predicting smoking cessation among US adults: An analysis of waves 1-3 of the PATH study](https://journals.plos.org/plosone/article?id=10.1371/journal.pone.0286883).

### Replace promised results with hypotheses

Revise statements promising:

- ROC-AUC above 0.80.
- Guaranteed improvement from SMOTE.
- Predetermined important predictors.

State these as questions to evaluate. A carefully validated simpler model is a valid project outcome.

### Qualify national and clinical claims

National population estimates require appropriate survey weights and design handling. The local folder contains some early-wave weight columns, but lacks the separate later-wave weight files needed for corresponding analyses. Weight selection must match the cohort and estimand; do not use one wave's weights indiscriminately across pooled intervals.

Clinical usefulness requires validation beyond this course project. Describe the output as a research prototype rather than a clinically validated tool.

Source: [Official PATH study documentation and weighting information](https://www.icpsr.umich.edu/web/NAHDAP/studies/36498).

### Verify the relapse-rate statement

Replace or verify the proposal's 85% relapse statement using a source specific to cigarette smoking and a clearly defined population, abstinence criterion, and follow-up duration. It should not be assumed to describe the proposed PATH cohort.

## 5. Suggested team responsibilities

For a three-person team:

| Responsibility | Main deliverables |
|---|---|
| Data and documentation | Variable dictionary, cohort extraction, missingness report, cohort flow counts |
| Modeling and evaluation | Split implementation, baselines, model comparison, calibration and metrics |
| Explainability and demonstration | SHAP analysis, Streamlit prototype, figures and presentation integration |

Agree on the cohort definition, prediction endpoint, and split rules together before working independently.

## 6. Suggested six-week schedule

| Week | Work |
|---|---|
| 1 | Finalize endpoint, map variables, check questionnaire eligibility |
| 2 | Construct the cohort, document exclusions and missingness, lock evaluation splits |
| 3 | Train prevalence-only and logistic-regression baselines |
| 4 | Compare Random Forest and XGBoost; tune using training/validation data |
| 5 | Assess calibration, explain predictions, build the demonstration |
| 6 | Complete the reserved test evaluation, report limitations, finalize presentation |

## 7. Final deliverables

- Reproducible cohort-building code.
- Wave-specific variable dictionary.
- Cohort inclusion/exclusion counts and missingness summary.
- Documented participant and temporal split strategy.
- Baseline and ensemble model comparison.
- Probability calibration and threshold-based evaluation.
- SHAP explanations with appropriate interpretation.
- Research demonstration.
- Revised proposal and final report.

The strongest submission will demonstrate a clearly defined prediction task, reproducible data preparation, and honest evaluation, even if a simple model performs best.
